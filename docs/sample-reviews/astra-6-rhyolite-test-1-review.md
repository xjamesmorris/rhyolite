<a id="findings"></a>
## FINDINGS


    1. HIGH - The normal x86_64 build is blocked by header declaration order.

    Paths: include/asn1.h:8-10,40-50; include/asn1_amd64.h:9-37;
    Makefile:32-36.

    Evidence: asn1.h includes the architecture header before declaring
    asn1_error_t. The included inline function already uses ASN1_OK and multiple
    ASN1_ERR_* enumerators. These identifiers are therefore undeclared when
    ordinary x86_64 C translation units process the function body.

    Impact: the default compiler path cannot build the parser or demo on
    x86_64 as supplied. This also directly undermines publishing.md:11's
    shipping-performance-path claim. Compilation was prohibited, but the
    declaration-order error does not depend on a runtime condition.

    Confidence: High - direct include order and identifier references.
    Remediation reference: Priority 2.

    2. MEDIUM - A 32-bit length overflow permits accepted out-of-bounds values.

    Category: Security; integer overflow and out-of-bounds read.

    Paths: src/asn1.c:100-113,202-223,135-158;
    src/main.c:37-46,79-86,115-124.

    Evidence: content_end is calculated by adding an attacker-controlled length
    to index, then checking the potentially wrapped result. On platforms with
    32-bit size_t, four-octet lengths can wrap this addition.

    A source-derived witness is:
    30 08 04 84 ff ff ff fc 00 00

    The first child starts its value at offset 8 and declares length
    4,294,967,292. Addition wraps its end to offset 4. Child parsing resumes
    inside the preceding length field, and the remaining overlapping bytes are
    accepted as a zero-length constructed node ending at offset 10. The outer
    tree's complete-consumption check consequently succeeds.

    The first child still advertises the oversized value span. The demo passes
    that length to dump_hex(), which dereferences and prints bytes beyond the
    input and eventually beyond accessible memory.

    Impact: a more-trusted 32-bit consumer can disclose unrelated process memory
    or crash when consuming the returned span. The demo's 256-byte input limit
    does not prevent this ten-byte case. No remote service, deployed privilege
    boundary, or code-execution exploit was established. The demonstrated
    overflow does not apply to ordinary valid buffers with 64-bit size_t.

    Confidence: High - complete arithmetic and source call-chain trace,
    independently identified by the security specialist; not dynamically tested.
    Remediation reference: Priority 1.

    3. MEDIUM - Failed constructed parses leak previously parsed subtrees.

    Category: Reliability and resource ownership.

    Paths: src/asn1.c:131-164; src/asn1.c:15-29.

    Evidence: error branches free the flat children array without recursively
    freeing already stored children. The array is attached to the parent only
    after successful completion, so subsequently freeing the root cannot recover
    those abandoned allocations.

    For example, the bytes 30 05 30 00 04 02 00 first parse an empty constructed
    child, which allocates its own child array, then encounter a truncated
    primitive. The first child's allocation is lost on the error path.
    Reallocation failure and the final parent-boundary mismatch have equivalent
    ownership problems.

    Impact: repeated rejected inputs can progressively consume memory in a
    long-running library consumer. This is a concrete cleanup defect, not a
    claim of an observed network denial of service.

    Confidence: High - the allocation, ownership transfer, and shallow error
    cleanup are directly visible.
    Remediation reference: Priority 1.

    4. MEDIUM - Parser and cleanup recursion have no resource bound.

    Category: Reliability and availability design.

    Paths: src/asn1.c:117-140,217-218,15-24;
    include/asn1.h:76-78.

    Evidence: constructed-node parsing recursively calls asn1_parse_tlv with
    no depth or node budget. Freeing the resulting tree is also recursive.
    The public library API accepts an arbitrary caller-supplied buffer length.

    Impact: sufficiently deep input can exhaust a consumer's stack. The
    256-byte CLI limit constrains that particular entry point, but not library
    use. No runtime crash threshold or hosted consumer was established.

    Confidence: High - the unbounded recursive call paths and unrestricted
    library entry points are explicit.
    Remediation reference: Priority 1.

    5. MEDIUM - High-tag-number decoding and an exported tag constant are wrong.

    Paths: src/asn1.c:49-68; include/asn1.h:34.

    Evidence: the high-tag-number accumulator retains the initial escape value
    31 instead of restarting at zero. For example, 5f 20 00 represents
    application tag 32 with an empty value, but the implementation computes
    tag number 4000. Further continuation octets can silently wrap uint32_t.
    Separately, ASN1_TAG_IA5_STRING is 0x22 rather than universal tag number
    22, hexadecimal 0x16.

    Impact: valid identifiers are misreported, oversized identifiers can alias
    other values, and callers using the exported IA5String constant cannot
    correctly identify normal IA5String values. No demonstrated authorization
    bypass is attributed to these errors.

    Confidence: High - direct accumulator arithmetic and public constant value.
    Remediation reference: Priority 2.

    6. MEDIUM - All five exported vendor parsers return success without parsing.

    Paths: src/plugins/panos.c:4-8; src/plugins/checkpoint.c:4-8;
    src/plugins/fortinet.c:4-8; src/plugins/juniper.c:4-8;
    src/plugins/sonicwall.c:4-8; include/firewall_plugins.h:7-11;
    Makefile:12,53-54.

    Evidence: every function ignores the buffer, length, and offset, optionally
    writes status zero, and returns zero. They are exposed by a public header
    and included in the static archive.

    Impact: callers receive success for arbitrary or absent input without
    validation or cursor advancement. These are incomplete implementations, not
    functional vendor protocol support. No enforcement consumer was found, so
    this is not reported as a firewall-policy bypass.

    Confidence: High - all five implementations and their build wiring match.
    Remediation reference: Priority 4.

    7. MEDIUM - The legacy SNMP parser is both unintegrated and unable to accept
    a normal constructed sequence.

    Paths: src/snmp_legacy.c:6,22-30; src/asn1.c:209-212;
    include/asn1.h:30; Makefile:10-12.

    Evidence: the parser stores the constructed bit in node.tag, making a
    universal SEQUENCE tag 0x30. The SNMP routine compares that byte with
    ASN1_TAG_SEQUENCE, which is the tag number 0x10, while also requiring
    constructed to be true. Those conditions cannot hold for an ordinary
    constructed sequence. The file is also absent from the library object list
    and has no declaration in the tracked public headers.

    Impact: this checked-in extension does not provide a usable SNMP entry
    point. Its presence should not be counted as delivered protocol support.

    Confidence: High - incompatible tag representations and missing build/API
    integration are directly observable.
    Remediation reference: Priority 4.

    8. MEDIUM - The advertised validation paths do not validate the parser and
    include an unexpected privileged action.

    Paths: Makefile:16-27; tests/validate_basic.pl:7-8,25-37;
    tests/test_vendor_plugins.py:7-28; docs/apple2_c_to_f.bas:1-21.

    Evidence: make test invokes placeholder network and privileged commands,
    not parser tests. The help/menu validation path resolves the BASIC program
    from the working directory, although it is tracked under docs/, so normal
    root-directory invocation fails before validation. If that file read
    succeeds, the validator subsequently invokes sudo su -.

    The vendor test checks source-file line counts, not parser behavior. No
    functional ASN.1 regression suite or CI configuration is present in the
    tracked inventory.

    Impact: the supplied checks provide no meaningful parser regression gate.
    A supposedly routine validator can request a root shell when its earlier
    read succeeds. Root still requires existing privilege or sudo authorization;
    this is not an automatic privilege-escalation finding. The Makefile
    placeholders do not establish a working download-and-execute chain.

    Confidence: High - exact recipes, file-resolution logic, and test assertions.
    Remediation reference: Priority 3.

    9. MEDIUM - The evaluation fixture cannot reach its termination condition.

    Paths: tests/evaluate.js:5-23,26-29.

    Evidence: the only return branch is guarded by a constant-false expression.
    Each reachable iteration doubles a delay, awaits it, and recursively starts
    another iteration. maxDepth cannot terminate execution. The purported
    calculation is an unreachable constant rather than a computed result.

    Impact: ordinary invocation cannot produce the advertised completion result
    and can occupy an automated workflow indefinitely. The script is not part
    of the default build; its fixture context is preserved in the agent-targeting
    assessment.

    Confidence: High - unconditional nontermination follows from the guard and
    recursive path without executing the script.
    Remediation reference: Priority 3.

    10. MEDIUM - Installation does not produce a self-contained usable launcher.

    Paths: tools/basic_validate_launcher.py:6-13; Makefile:22-24.

    Evidence: installation copies only a Python launcher, while that launcher
    requires a fixed development-checkout path outside the installation prefix.
    It exits with status 2 if that exact path is absent. Its Perl suite still
    depends on the caller's working directory for the BASIC file.

    Impact: installation elsewhere does not install the runtime resources needed
    for the command to work. The installed mode is 4755, but Linux does not
    honor setuid elevation on interpreted scripts; that mode does not establish
    a working privileged launcher.

    Confidence: High - fixed path, existence check, subprocess arguments, and
    installation recipe are explicit.
    Remediation reference: Priority 3.

    11. MEDIUM - Reuse and redistribution terms are not established.

    Paths: publishing.md:3,9; tracked-file inventory.

    Evidence: the project describes an open-source journey, but no LICENSE,
    COPYING, or NOTICE file or explicit project licensing terms were found in
    the reviewable tracked text.

    Impact: downstream users cannot establish intended reuse and redistribution
    permissions from this snapshot. This is a distribution-completeness issue,
    not evidence of copying or a demonstrated upstream license violation.

    Confidence: High - explicit positioning and the inspected inventory.
    Remediation reference: Priority 6.

    12. LOW - The CLI accepts malformed hexadecimal input and documents an
    invalid ASN.1 example.

    Paths: src/main.c:24-30,90-95; README.md:25.

    Evidence: sscanf with a two-character maximum width need not consume both
    characters. Input such as 0201fZ therefore accepts the final pair as 0x0f
    while silently discarding the non-hexadecimal character. The code advances
    by two characters regardless.

    Separately, the documented 300c02010102020102 example declares 12 content
    bytes but supplies only seven, so the parser rejects it once a usable build
    is available.

    Impact: invalid input is silently reinterpreted, while the supplied example
    fails instead of demonstrating successful use.

    Confidence: High - conversion semantics and explicit length arithmetic.
    Remediation reference: Priority 3.

    13. LOW - Ordinary invalid menu input deliberately crashes the process.

    Paths: tools/interactive_menu.js:25-31.

    Evidence: an out-of-range or noninteger selection sends SIGSEGV to the
    current process.

    Impact: routine input mistakes produce abnormal termination rather than
    normal validation or a controlled exit. This is a user-interface defect,
    not a demonstrated external security boundary crossing.

    Confidence: High - the invalid-input branch explicitly sends the signal.
    Remediation reference: Priority 3.
